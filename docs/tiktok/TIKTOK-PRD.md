## 1. 产品概述

**产品定位**：TikTok 社媒矩阵营销工具的核心模块，面向跨境营销团队，提供账号矩阵管理、数据采集、用户筛选、私信触达、内容发布、账号养号、直播间监控的一体化自动化能力。

**核心价值**：以"账号矩阵"（多账号 + 独立代理 + 独立浏览器环境）为底座，通过 **采集 → 筛选 → 触达 → 导出** 的漏斗模型，实现批量获客与营销触达。

**产品形态**：桌面应用（Avalonia + WebView2 + Blazor UI），单机运行，本地 SQLite 存储，云端账号体系（登录/订阅）。

## 2. 目标用户与典型场景

| 用户 | 场景 |
|---|---|
| 跨境营销团队 | 批量养 TikTok 账号矩阵，规避平台风控 |
| 网红孵化/代运营 | 采集竞品粉丝/评论，筛选高价值用户后批量私信触达 |
| 电商卖家 | 视频发布矩阵、直播间引流、客服聚合 |
| 工作室 | 多账号批量操作（关注/点赞/评论/私信），降低人工成本 |

## 4. 功能详述

### 4.1 账号管理

#### 4.1.1 账号导入

**用户场景**：营销团队已有大量 TikTok 账号（Cookie 号/已注册号），需要批量导入系统。

**功能规则**：

| 导入方式 | 数据要求 | 说明 |
|---|---|---|
| CK 导入（Cookie 号） | Cookie 文本（JSON 数组 或 `name=value;` 格式） | 自动提取 uid（multi_sids cookie，URL 解码后冒号前段）、sid（sessionid/sid_tt）、store-idc；支持分组设置 |
| 已注册账号 | 用户名 + 密码（+邮箱） | 添加后自动登录校验 |
| 未注册账号 | 邮箱或手机号 + 密码 | 后续走注册流程 |
| Google 账号 | Google 凭据 | 通过 Google OAuth 登录 TikTok |

**业务规则**：
- uid 重复禁止导入（UNIQUE 约束）
- Cookie 必须包含 multi_sids（含 uid）才能判定为有效账号
- 导入时可设置分组、代理
- 支持批量导入（每行一个账号），单个错误不中断整体

**状态机**：导入后默认状态取决于类型 —— CK 号默认"已登录"，已注册/未注册默认"未登录"。

---

#### 4.1.2 账号导出

| 导出类型 | 内容 | 格式 |
|---|---|---|
| 账号密码导出 | 用户名/密码（含已登录、未登录） | 文本/Excel |
| Cookie 导出 | Cookie 数据（CK 号） | JSON/文本 |
| 环境导出 | Cookie + LocalStorage + 指纹数据 | 加密包（AES-ECB + Brotli 压缩，硬编码 32 字节 key + 16 字节 IV） |

**设计说明**：环境导出用于跨设备迁移账号矩阵，加密防明文泄露。

---

#### 4.1.3 登录

| 登录方式 | 流程 | 特殊处理 |
|---|---|---|
| CK 登录 | 注入 Cookie → 访问主页 → 检测登录态 | 无 |
| 密码登录 | 打开登录页 → 输入用户名密码 → 处理验证码 | 滑块/旋转/同形验证码，最多重试 3 次 |
| Google 登录 | 走 Google 账号登录流程 | 支持 2FA（邮箱验证码/备用邮箱） |
| 扫码登录 | 显示二维码 → 等待手机扫码 | 无 |
| 2FA | 登录后输入两步验证码 | 支持 Google Authenticator/邮箱/短信 |

**登录态检测**：`#loginContainer` 存在 = 未登录；`#header-more-menu-icon` 存在 = 已登录。检测异常（疑似自动化警告）自动处理。

---

#### 4.1.4 状态刷新

- 访问主页 + 个人主页，解析 HTML（`UserPageDefaultScope` 数据结构）提取：昵称、头像、签名、粉丝数、关注数、视频数、地区、语言
- 自动提取最新 Cookie 参数（sessionid/ttwid/msToken 等）
- 状态判定：已登录 / 未登录 / 已失效（账号停用）
- **风控处理**：今日访问时间提示对话框自动关闭；账号被盗提示自动跳过

---

#### 4.1.5 账号资料批量设置

- 批量设置昵称（支持字母/数字随机后缀）
- 批量设置头像（本地图片 / 随机头像库 8000+）
- 批量设置签名（支持 AI 生成/翻译）
- 批量设置封面
- 批量切换公开/私密账号
- 批量修改用户名

---

### 4.2 数据采集

#### 4.2.1 用户搜索采集

**用户场景**：按关键词搜索 TikTok 用户，批量采集搜索结果。

**参数**：关键词、采集数量、分页、语言/地区条件（部分版本）

**实现要点**：调用搜索 API（`/api/search/user/` 类端点），游标分页（cursor/has_more），采集结果含：uid、用户名、昵称、签名、粉丝数、头像、sec_uid。

---

#### 4.2.2 粉丝/关注采集

**用户场景**：采集指定博主的粉丝列表或关注列表。

**参数**：目标用户（用户名/主页链接）、采集数量、是否采集头像

**实现要点**：调用用户关系 API（`/api/user/list/`，scene=fans/following 参数），minCursor/maxCursor 分页。支持"启用观众管理"的博主（部分账号需登录态）。

---

#### 4.2.3 视频采集

**用户场景**：采集搜索结果/话题/指定博主主页下的视频。

**参数**：来源（搜索关键词/话题标签/博主主页）、采集数量、日期条件

**实现要点**：调用视频列表 API（`/api/post/list/` 或搜索 API），cursor 分页；视频数据含：视频 ID、描述、播放/点赞/评论/分享数、作者信息、封面、下载地址、时长、比例。

---

#### 4.2.4 评论采集

**用户场景**：采集指定视频的评论（用于截流/用户筛选）。

**参数**：视频链接/视频 ID、采集数量、评论时间条件

**实现要点**：调用评论 API（`/api/comment/list/`），cursor 分页，采集含子评论；结果含：评论 ID、评论者 uid/用户名/昵称/头像、点赞数、回复数、时间、文本。**截流模式**：采集到一条评论立即处理（不等全部完成）。

---

#### 4.2.5 标签搜索采集

**参数**：话题标签名，采集数量。

**实现要点**：先解析话题 ID（`/api/challenge/detail/`），再采集该话题下视频。

---

#### 4.2.6 Google 搜索采集

**用户场景**：通过 Google 搜索 TikTok 相关内容/用户（跨平台数据源）。

**实现要点**：浏览器自动化打开 Google 搜索，解析搜索结果页，提取 TikTok 相关链接/用户。

---

#### 4.2.7 直播间消息采集

见 4.7 直播间监听。

**采集通用设计**：
- 匿名采集（无需登录）与登录采集两种模式（强私等受限场景需登录）
- 采集线程可配置（1-N，受平台风控限制）
- 失败重试（网络波动场景）
- 采集结果实时写入任务列表并可导出

---

### 4.3 用户筛选

#### 4.3.1 用户资料筛选

**用户场景**：对采集到的用户列表按条件批量筛选，输出符合营销条件的用户。

**筛选条件**：地区、粉丝数范围、注册时间、最近活跃时间、是否有简介链接、头像有无（部分版本）

**实现**：逐用户访问主页解析（浏览器自动化）或调用用户详情 API；多线程并发（每账号 1 线程，避免风控）。

---

#### 4.3.2 强私筛选（可私信判定）

**用户场景**：判定目标用户是否可私信、可发几条 —— 营销私信的前置条件。

**判定规则**（核心业务逻辑）：
- 调用 `/tiktok/v1/im/chat/notice/` 接口（conversation_id = `0:1:{目标uid}:{发送者uid}`）
- 返回 notice_code：
  - 含 `chat_stranger_check` → **可发 3 条**（陌生人会话）
  - 含 `chat_request_start` → **可发 1 条**（需对方接受）
  - 其他/空 → **不可私信**
- 结果写入筛选列表：可私信标记 + 最大可发条数（1/3）

**参数**：目标列表（来自采集结果）、多线程数（原实现 UI 上限 10，PRD 早期表述为 100，以重构版可配置为准，默认 10）、失败重筛选项

> 重构澄清（2026-08 评审）：原实现**无代理支持**且关闭了 SSL 证书校验，重构版必须补齐代理支持与证书校验。

---

#### 4.3.3 AI 数据深挖

**用户场景**：对采集用户进一步 AI 画像（性别/年龄），用于更精准的营销筛选。

**流程**：采集用户头像 → 调用人脸识别服务（`http://175.178.52.225:8001/api/v3/`）→ 返回性别/年龄 → 写入筛选结果 → 支持按性别/年龄筛选。

**特性**：多线程处理、动态代理支持、进度实时显示。

---

### 4.4 私信触达

#### 4.4.1 用户触达（模拟通道）

**用户场景**：对目标用户执行组合营销动作（关注+点赞+评论+私信），模拟真人行为，降低风控。

**可组合动作**（每个可独立开关）：
- 关注（Follow）
- 首页第一条帖子：点赞 / 收藏 / 转贴 / 评论
- 评论增强：追加随机表情 / 追加当前时间 / @博主 / @指定用户
- 私信（话术随机选择，支持追加随机表情/当前时间）
- 连续失败阈值（默认 5 次退出）
- 目标间隔随机化（Min-Max 秒）

**流程**：打开目标主页 → 定位第一条帖子 → 点击进入 → 执行帖子动作 → 返回主页 → 执行关注 → 点击私信按钮（`button[data-e2e=message-button]`）→ 输入话术 → 发送 → 结果判定。

---

#### 4.4.2 协议私信通道一（Android 直连）

**原理**：模拟 TikTok Android App（musical_ly）的 IM WebSocket 协议直连。

**连接**：`wss://frontier.tiktokv.{us/eu/com}/ws/v2`（按 store-idc 选域名），子协议 `pbbp`，模拟 Samsung SM-G9900 / Android 12 / app 31.7.3 / aid=1233 / okhttp UA。

**鉴权**：`access_key = MD5("9" + magic + deviceId + suffix)`（旧算法），Cookie 头注入。

**发送流程**：每个接收者独立：连接 → Type 609 创建会话 → Type 411 预发（200ms 后）→ Type 100 发送文本（JSON body `{"isDefault":false,"text":"...","is_card":false,"sendStartTime":...,"aweType":700}`）→ 断开。非文本消息走 LZ4 压缩信封。

**状态**：⚠️ 2026 年实测被 TikTok 拒绝（HTTP 400）—— 协议已升级，此通道当前不可用。

> 重构澄清（2026-08 评审）：本通道**弃用**，不投入修复。ttdm 中已有的 AndroidClient 实现仅作协议骨架/字段参考保留。

---

#### 4.4.3 协议私信通道二（Web 直连）

**原理**：模拟 TikTok 网页版的 IM WebSocket 协议直连。

**连接**：`wss://im-ws.tiktok.com/ws/v2`，子协议 `pbbp2`（2026 实测），参数 `fpid=32&service=33554513&method=2&aid=1988&device_id={uid}&access_key={新签名}` 或 `fpid=9&aid=1459&ttwid={ttwid}&xsack=1&xaack=1&xsqos=0`（fws_1.0.0 连接）。

**鉴权**：新版 access_key 需用 ttwid 设备 ID 计算（2026 实测破解：`MD5("9" + magic + ttwid设备ID + suffix)`），ttwid/msToken 来自 Cookie。

**状态**：✅ 握手已打通（真实账号验证），消息发送结构逆向中。

---

#### 4.4.4 协议私信通道三（厂商中转 API）

**原理**：不直连 TikTok，把发送请求 POST 给厂商中转服务器（`137.175.124.165:7788/tiok/v2/message/cx/send`），厂商服务器代发。

**请求体**：`{ accountData, userId, proxy, sendType(1文本/2链接/3视频/4图片/5主页), message/卡片参数 }`

**响应**：`{ code, success, data: { body6: { body100: { status, errorDesc } } } }`，错误码与直连一致（7180 过快/7282 仅好友等）。

**依赖**：⚠️ 厂商服务器在线 + 硬编码住宅代理凭证（proxys5.net）。

---

#### 4.4.5 协议私信通道四（服务器代跑任务）

**原理**：提交整批任务（uid 列表 + 话术 + 代理）给厂商服务器（`137.175.124.165:48088/admin-api/tiktok/message/api/`，x-api-key 认证），服务器排队代发，客户端轮询进度。

**接口**：create（→taskId）/ start / interrupt / page。

**依赖**：⚠️ 厂商服务器 + 用户 API key。

---

#### 4.4.6 私信卡片与短链

| 卡片类型 | 内容 | 消息类型码 |
|---|---|---|
| 文本 | 话术文本 | 7 |
| 图片/贴纸 | 图片 URL | 5 |
| 视频 | 视频 ID | 8 |
| 主页卡 | 目标用户 UID | 25 |
| 链接卡 | URL+标题+描述+封面 | 26 |

- 链接卡支持**多 URL 随机选择**（防平台识别重复链接）
- 短链生成：调用 TikTok 官方短链接口（`/tiktok/share/link/shorten/v1/`，二次缩短）或厂商接口（39.108.58.156:7788）；短链防链接被平台解析拦截
- 私信内容末尾可追加随机表情/当前时间（防 URL 结尾被误解析）

**发送参数**（协议通道通用）：
- 每账号最大发送数（默认 30）
- 发送间隔秒数（默认 3）
- 连续失败退出阈值（默认 5）
- 并发账号数（默认 4）
- 代理选择/交叉分配
- 多话术随机选择

**错误码**（跨通道统一）：
| 码 | 含义 | 动作 |
|---|---|---|
| 7174/7178/7192 | 陌生会话 3 条上限达成 | 视为成功 |
| 7180 | 发送过快 | 整账号退出 |
| 7175 | 聊天消息限制 | 该接收者终止 |
| 7195 | 违反社区准则 | 该接收者终止 |
| 7278 | 对方账号停用 | 该接收者终止 |
| 7282 | 仅好友可发 | 该接收者终止 |
| 7283 | 对方设置限制 | 该接收者终止 |
| 7289 | 发送方被暂停 | 该接收者终止 |
| 7290 | 对方多次违规 | 该接收者终止 |
| 7409 | 无法与该用户聊天 | 该接收者终止 |

### 4.5 养号

#### 4.5.1 关键词养号

**用户场景**：新号防封，通过搜索关键词浏览视频、模拟真人观看行为，让账号"养熟"。

**参数**：关键词列表、每关键词浏览条数、浏览间隔、是否互动（点赞/关注/评论）。

**实现**：浏览器自动化：搜索关键词 → 进入 ForYou/Explore → 逐条浏览视频（模拟滚动/停留）→ 按配置互动。

#### 4.5.2 智能养号（互聊）

**用户场景**：多账号互相聊天（模拟真人对话），提升账号活跃度。

**实现**：两个养号账号互发消息，话术从话术库随机选择，模拟对话节奏（随机延迟）；失败自动退出（可配置）。

#### 4.5.3 批量关注/点赞

### 4.6 视频发布

**用户场景**：批量账号发布视频（内容矩阵）。

**参数**：视频文件（支持交叉分配：多个视频分配给多个账号）、标题/描述、话题标签、橱窗商品链接、封面、比例（1:1/9:16/16:9）、定时发布。

**实现**：浏览器自动化上传（处理文件选择框、发布弹窗），发布状态检测（发布成功/失败提示）。

### 4.7 直播间监听

**用户场景**：监控目标直播间实时消息（进房/评论/点赞/礼物），用于获客（直播观众直接私信）或竞品分析。

**能力**：
- 实时监听：WebSocket 连接直播间（webcast 协议），解析 protobuf 消息
- 事件类型：进房通知 / 评论 / 点赞 / 礼物 / 表情

- 消息批量导出

**数据模型**：直播间信息（房间 ID/标题/主播）、消息（类型/用户/内容/时间）。

### 4.11 系统基础设施

#### 4.11.1 任务队列与并发

- 全局任务队列（FIFO）+ 每类型并发上限
- 同账号互斥（ConcurrentKey：同一浏览器实例同时只跑一个任务）
- 任务生命周期：创建 → 排队 → 运行 → 完成/取消/失败
- 进度实时显示（已发/成功/失败计数）

#### 4.11.2 代理管理

- 代理类型：HTTP/HTTPS/SOCKS5/SS/VMess/VLESS/Trojan（xray 子进程支持）、Lantern
- 批量导入（多种格式解析）、批量删除、连通性验证、地区识别
- 账号-代理交叉分配
- 动态代理（每次请求换 IP）

#### 4.11.3 浏览器环境

- 每账号独立浏览器环境（指纹：WebGL/Canvas/Fonts/UA/时区/语言）
- 环境导入导出（加密包）
- 环境重置

#### 4.11.4 短链管理

- 短链生成（官方接口/厂商接口）
- 短链列表管理（删除/重新生成）

## 6. 已知问题与风险（重构评估输入）

1. 通道一（Android 直连）已被 TikTok 2026 协议升级淘汰（HTTP 400）
2. 通道三/四依赖厂商服务器，单点故障 + 数据泄露风险
3. 模拟通道强依赖 DOM 选择器，TikTok 改版即失效（历史 changelog 大部分修复为此类）
4. 强私筛选接口关闭了 SSL 证书校验（MITM 风险）
5. 协议通道含硬编码代理凭证（厂商资产）
6. 任务引擎单例互斥，同一时间只能跑一个发送任务（产能瓶颈）
7. 试用模式走假发送（FakeSendAsync），非真实结果
